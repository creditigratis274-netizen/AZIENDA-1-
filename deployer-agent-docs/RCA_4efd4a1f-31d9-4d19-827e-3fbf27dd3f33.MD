# RCA — run 4efd4a1f-31d9-4d19-827e-3fbf27dd3f33 (iqfoam-business)

## Symptom
Deploy failed at the `deploy` (k8s rollout) step. Pod `r-4efd4a1f-...-8k57n` went into **CrashLoopBackOff (early), restarts=3, lastExit=1/Error**. The backend crashes on startup and exits.

## Root cause — confirmed (code + DB inspection)
The app uses a **physical per-company database** tenancy model. In `backend/tenancy.py`:
```python
def tenant_database(client, base_database, company_id):
    if not company_id or company_id == DEFAULT_COMPANY_ID:   # DEFAULT_COMPANY_ID = "superiqfoam"
        return base_database
    return client[f"{base_database.name}__{company_id}"]      # <-- separate DB per company
```
`COMPANY_PROFILES` (server.py:106) includes `{"id": "imraan-plastics", ...}`, a **non-default** company. On startup `on_startup()` → `initialize_multi_company()` → `initialize_empty_company("imraan-plastics")` opens database **`iqfoam-business-test_database__imraan-plastics`** and runs `settings.count_documents({})`.

In production the app's MongoDB user is provisioned with access to **exactly one database** — the app's own DB. Confirmed via a read-only query on this run: the resolved `db_name` is **`iqfoam-business-test_database`** (60 collections, all tenants already stored in it and scoped by a `company_id` field via `ScopedCollection`). The Atlas user is **not authorized** on any other database name, so the attempt to open `..._database__imraan-plastics` returns `code 13 Unauthorized`, the startup handler raises, and the process exits → CrashLoopBackOff → deploy step fails.

This is new behaviour in this run. Prior runs (e.g. 9b4807f2, succeeded 2026-11-16 08:44) deployed fine — the per-company separate-database routing is the regression.

## What this is NOT
- NOT a manifest/Dockerfile/entrypoint issue.
- NOT a secrets issue — `MONGO_URL` / `DB_NAME` are the correct platform-managed system keys and resolve to the right provisioned database (`iqfoam-business-test_database`).
- NOT a tier/OOM issue — exit is a clean application startup failure (exit 1), not OOMKilled.

## Fix (Code — E1 must apply; requires redeploy)
The Emergent platform gives each app a single database with a user scoped to that one DB; the app cannot read/write arbitrary additional databases on the cluster. Keep all tenants in the single provisioned database and rely on the existing `company_id` scoping that `ScopedCollection` already injects.

Minimal change — make `tenant_database()` always return the base database:
```python
def tenant_database(client, base_database, company_id):
    return base_database
```
This removes the `{base_db}__{company_id}` physical split so every tenant lives in `iqfoam-business-test_database`, isolated by the `company_id` field (already enforced by `ScopedCollection` / `_scope_filter` / `_stamp_document`). Also review `backup_database_names()` (server.py:11503) which enumerates the same per-company DB names.

Note: any data written to separate per-company DBs during preview would need migration into the single DB before relying on this — but in production those separate DBs were never created (the user has no access), so no prod data is lost.

## Verification note
Could not reproduce against a live DB in the sandbox (no production Mongo credentials are injected into the eph pod). Diagnosis is proven from: the crash traceback, the `tenant_database` source, and a read-only `list_collections` confirming the single authorized production DB name.
