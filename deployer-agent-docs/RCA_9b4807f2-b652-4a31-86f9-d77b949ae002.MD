## (3) The two separate databases
- `iqfoam-business-test_database__iqfoam-manufactoring` and `__iqfoam-whole-sallers`: the mongo_query tool is scoped server-side to the run's resolved db_name (`iqfoam-business-test_database`) and has NO database-override parameter, so it CANNOT read those DBs directly. Not attempted = not confirmed empty/full.
- Authorization: the production Mongo user is **NOT authorized** on the per-company suffixed databases. Proof — failed run 4efd4a1f logged 7× `not authorized on iqfoam-business-test_database__imraan-plastics ... 'code': 13, 'codeName': 'Unauthorized'`. Same user, same cluster, identical naming pattern ⇒ it would be equally unauthorized on `__iqfoam-manufactoring` and `__iqfoam-whole-sallers`. (That crash happened on the first company iterated — imraan-plastics — so manufactoring/whole-sallers suffixed DBs do not appear by name only because iteration aborted, not because they are accessible.)
- Earlier successful deploys (cbdaa728, 02237a7d on Nov 14) are >24h old — outside the Loki 24h log window — so their read/write activity to those DB names could NOT be retrieved.

## (4) Did the live app ever write Manufacturing/Wholesalers invoices or customers?
- Last-24h live-run logs for those company_ids are all **GET reads** (interface-settings, access/workers, intercompany/products), all 200 except one 403 on `/api/access/workers?company_id=iqfoam-manufactoring`. No write (POST/PUT) of invoices or customers for those companies observed.
- Consistent with DB counts: 0 invoices / 0 customers for manufactoring & whole-sallers in the main DB. No evidence the live app wrote those companies' invoices/customers into the main DB.

## Data-loss assessment
No evidence of data LOSS. Manufacturing / Wholesalers / Imraan-plastics operational data is simply NOT in the main DB — it was never migrated there (only superiqfoam was). Their data, if present, still resides in the separate `__<company>` databases, which the current production Mongo user cannot read (code 13 Unauthorized). Those DBs were not deleted by anything observed here. To bring that data into the new single-DB model, it must be exported/copied from the suffixed DBs (requires Atlas-level access/authorization) and inserted into `iqfoam-business-test_database` stamped with the right company_id — a deliberate migration, not something the live app does automatically.
